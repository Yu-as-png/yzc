# 04 网页 B/S 版 · 原子功能详解：首页信息流与公告检索（Vue 3）

> 本篇目标：讲透网页版最核心的复合原子功能——首页。覆盖「头条式双栏布局（频道 Tab + 信息流 + 热榜侧栏）」「顶栏搜索的跨组件传参」「公告关键字检索」三块。本篇之后，"一个列表页怎么组织"的模式就定型了，我的头条、管理后台的表格页全是它的变体。

## 一、为什么先写首页

1. **用户旅程的入口与产品脸面。** 登录后第一屏，头条式布局的全部设计语言（红主色/频道 Tab/无卡片信息流/sticky 侧栏）在这里定型。
2. **三条数据流汇于一页**：头条列表（带 4 个查询参数）、热榜（按赞 Top10）、公告（可检索）——多请求编排与状态管理的样板。
3. **搜索跨组件**：输入框在 `App.vue` 顶栏、结果在 `Home.vue`，靠路由 query 传递——Vue Router 在"组件间说话"的最小样本。

## 二、功能行为定义

- 顶栏（`App.vue`，全站共享）：红「微头条」logo、导航、灰底搜索框（回车跳 `/?q=关键字`）、头像昵称角色、退出。
- 首页（`Home.vue`）双栏：
  - 左栏：频道 Tab（推荐+8 类型，选中红下划线）+ 排序下拉（时间/赞/评/浏览）→ 信息流（标题悬停红、meta 灰阶、右侧阅读数）→ 分页
  - 右栏 sticky：热榜 Top10（前三红角标、`N赞`）+ 公告卡（最新 3 条 + "查看全部/搜索公告"展开检索）
- 搜索：顶栏输入回车 → `route.query.q` → 首页读取进 keyword → 列表即时过滤；结果态显示"…的搜索结果 · N 条"与"清除"。
- 公告检索：展开后输入关键字（标题∪内容模糊，服务端 `?keyword=`）。

## 四、请求契约：`api.js`（全文）

```js
// 文件:web/src/api.js
// 简单 fetch 封装，基址走 vite 代理 /api -> localhost:3000
export async function request(path, { method = 'GET', body } = {}) {
  const token = localStorage.getItem('token') || '';
  const res = await fetch('/api' + path, {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: 'Bearer ' + token } : {}),
    },
    body: body !== undefined ? JSON.stringify(body) : undefined,
  });
  let json;
  try { json = await res.json(); } catch { throw new Error('服务器响应异常'); }
  if (json.code !== 0) throw new Error(json.msg || '请求失败');
  return json.data;                     // 直接返回 data，调用点少剥一层
}
export const api = {
  get: (path, params) => request(path + (params ? '?' + new URLSearchParams(params) : '')),
  post: (path, body = {}) => request(path, { method: 'POST', body }),
  put: (path, body = {}) => request(path, { method: 'PUT', body }),
  del: (path) => request(path, { method: 'DELETE' }),
};
```

走读：

- **与 03 版的差别是错误策略**：Electron 版折叠错误为返回值（`{code:1}`），网页版**抛异常**——Vue 模板里 `try/catch` 集中在 load 函数，成功路径直接用 `data`，两种风格各自适配框架习惯。
- **`api.get` 支持 params 对象**：`api.get('/headlines', { keyword, typeId, sort, page })` 自动 `URLSearchParams` 序列化，中文关键字免手工 `encodeURIComponent`——公告检索 `api.get('/notices', { keyword })` 直接受益。
- 相对路径 `/api` 走 Vite 代理（`vite.config.js`）：开发态代理到 3000，与 Electron 直连形成对照——B/S 的"同源"是代理给的。

## 五、顶栏搜索：`App.vue`（节选）

```vue
<!-- 文件:web/src/App.vue -->
<script setup>
const router = useRouter();
const q = ref('');
function doSearch() {
  if (!q.value.trim()) return;
  router.push({ path: '/', query: { q: q.value.trim() } });   // 搜索词进 URL
  q.value = '';
}
</script>
```

走读：**搜索词是路由状态不是组件状态**。放进 `?q=` 有三个便宜：可刷新（分享/收藏带条件）、从详情返回首页条件不丢、顶栏与首页解耦——顶栏只负责"把词写进 URL"，读不读、怎么用是首页的事。

## 六、首页本体：`Home.vue`（关键段 + 走读）

### 三流并行加载

```vue
<!-- 文件:web/src/views/Home.vue -->
<script setup>
onMounted(async () => {
  if (route.query.q) keyword.value = String(route.query.q);    // 接顶栏搜索
  try {
    const [n, t, h] = await Promise.all([
      api.get('/notices'),
      api.get('/types'),
      api.get('/headlines', { sort: 'like', page: 1, pageSize: 10 }),   // 热榜
    ]);
    notices.value = n; types.value = t; hot.value = h.list;
  } catch (e) { err.value = e.message; }
  load();
});
</script>
```

走读：首屏三个请求 `Promise.all` 绑架（首屏要么一起到要么一起错，均分 loading 语义）；后续频道切换走独立 `load()` 不再碰公告/热榜——**首屏一次性、交互局部化**，是列表页请求编排的纪律。

### 列表查询与频道切换

```js
async function load() {
  const data = await api.get('/headlines', {
    keyword: keyword.value, typeId: typeId.value,
    sort: sort.value, page: page.value, pageSize,
  });
  list.value = data.list; total.value = data.total;
}
function pickChannel(id) { typeId.value = id; page.value = 1; load(); }
```

走读：频道/排序/搜索/翻页全部收敛到 `load()` 一个函数，参数由 state 提供——改任何筛选项都是"改 state → 调 load"，不存在第二套查询路径。`pickChannel` 重置 `page=1`（切频道停在第 3 页是经典 bug）。

### 信息流渲染（节选）

```html
<router-link v-for="h in list" :key="h.id" class="feed-item" :to="'/headlines/' + h.id">
  <div class="feed-body">
    <div class="feed-title">{{ h.title }}</div>
    <div class="feed-meta">
      <span class="author-dot" :style="{ background: avatarColor(h.author) }"></span>
      <span>{{ h.author }}</span><span class="sep">·</span>
      <span>评论 {{ h.comment_count }}</span><span class="sep">·</span>
      <span>赞 {{ h.like_count }}</span><span class="sep">·</span>
      <span>{{ shortTime(h.create_time) }}</span>
      <span class="type-tag">{{ h.typeName }}</span>
    </div>
  </div>
  <div class="feed-stat"><b>{{ h.view_count }}</b><i>阅读</i></div>
</router-link>
```

走读：整条卡片是 `router-link`（可中键新开标签）；`feed-title` 两行 clamp、悬停变红，`.feed-item` 无卡片阴影只有行分隔线——**今日头条信息流的还原度全在 style.css 的 `.feed-*` 一组类**，组件零内联样式。`avatarColor` 是姓名哈希六色圆点，与 Electron 版同一纯函数。

### 公告检索（节选）

```js
const noticeKeyword = ref('');
const noticeList = ref([]);
const showNotices = ref(false);
const searchNotices = async () => {
  noticeList.value = await api.get('/notices', { keyword: noticeKeyword.value });
  showNotices.value = true;
};
```

走读：公告检索走**服务端过滤**（`GET /api/notices?keyword=`，NestJS `NoticesController.list` 里 title∪content includes）——与头条搜索同一模式，模糊匹配规则只有服务端一份；"展开才检索"让首屏不为低频功能多背一个请求。

## 七、如何验证

前置：`server-nestjs` 已启动；`cd web && npm run dev`（:5173）。

操作剧本：

1. `admin/123456` 登录进首页。预期：频道 Tab 9 个、信息流有 meta 与阅读数、右栏热榜前三红角标 + 公告卡；滚动时右栏 sticky。
2. 点「财经」。预期：URL 不变（频道是组件 state），列表只剩财经，频道下划线移动。
3. 顶栏输入"票房"回车。预期：URL 变 `/?q=票房`，列表为命中项，出现「“票房”的搜索结果 · N 条 · 清除」。
4. **刷新页面**。预期：搜索条件保留（query 在 URL 里）——这是本设计的行为证明。
5. 公告卡点"查看全部/搜索公告"，输入"维护"。预期：仅命中"系统维护通知"。
6. 点热榜任一条。预期：进详情；浏览器返回后 `?q=票房` 条件仍在。

常见故障对查：

| 现象 | 原因 |
|---|---|
| 请求 404/CORS | Vite 没起在 5173 或代理配置被改（检查 `vite.config.js` server.proxy） |
| 搜索后刷新丢条件 | 有代码把 keyword 只存 ref 没读 `route.query.q` |
| 公告搜索无结果 | 后端是旧构建（无 keyword 过滤）：`server-nestjs` 重新 `npm run build` |
